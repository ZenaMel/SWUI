# ADR 0004 — ProcessEvent override for delegate payload serialization

## Status

Accepted (2026-05-29)

## Context

SWUI needs to serialize observed delegate broadcast parameters into JS CustomEvent `detail` payloads at runtime. Two approaches were considered:

1. **Per-signature Fire functions**: Declare `FireBool(bool)`, `FireString(FString)`, `FireInt(int32)`, etc. and bind the matching one based on delegate signature inspection at ObserveDelegate time.
2. **ProcessEvent override**: Bind a single no-op UFUNCTION (`DelegateHook`) to every observed delegate, override `ProcessEvent` to intercept the call, read parameters from the raw `Parms` buffer using the stored `SignatureFunction`'s property offsets.

## Decision

Use approach 2 (ProcessEvent override). Rationale:

- **Combinatorial explosion problem**: Approach 1 requires a Fire function for every param type + count combination. For 1-param: 6 functions. For 2-param: up to 6^2 = 36 combinations. This is not maintainable.
- **Generic and future-proof**: Any delegate signature is supported without adding new functions.
- **Verified against UHT output**: The `_Script_Parms` struct generated by UHT in `_DelegateWrapper` functions has the same layout as the `SignatureFunction` property offsets — confirmed by inspecting `OneVOnlineSubsystem.gen.cpp:309-317`.
- **No stack-hacking**: Params are read from the `Parms` buffer using standard `ContainerPtrToValuePtr`, not from the `FFrame` stack (which doesn't contain them for zero-param functions).

## Consequences

**Positive:**
- Single bridge class handles any delegate signature
- No new functions needed when new delegate types are added
- Runtime payload shape matches generated TS types (same `SignatureFunction` is source of truth for both)

**Negative:**
- `ProcessEvent` is a virtual on `UObject` — overriding it requires careful delegation to `Super::ProcessEvent` for non-hook calls (Serialize, FinishDestroy, etc.)
- The hook function must be a no-op body — the real work happens in the override, which may confuse developers reading the header
- `ProcessEvent` is called for every UObject event (GC, serialization, etc.) — the `Function == HookFunction` check is a fast early-out
