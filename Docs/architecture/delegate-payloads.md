# Delegate payloads — serializing UE delegate params to JS CustomEvents

## What this solves

SWUI observes `UPROPERTY(BlueprintAssignable)` delegates and dispatches JS `CustomEvent`s when they fire. Until fixed, dispatched events carried an empty `detail: {}` — the payload metadata existed only in the generated TypeScript contract, never at runtime.

## Mental model

```
UE/AS delegate fires (e.g. OnRoomHostResult.Broadcast(true))
 → FMulticastDelegateProperty invokes bound FScriptDelegate
 → ProcessEvent called on USwuiDelegateBridge
 → Bridge reads real params from Parms buffer via SignatureFunction property offsets
 → Serializes by param name: {bSuccess: true}
 → document.dispatchEvent(new CustomEvent("ns.OnRoomHostResult", {detail: {bSuccess: true}}))
 → React addEventListener receives event.detail.bSuccess
```

The **Delegate SignatureFunction** is the source of truth for both the generated TS event helper type AND the runtime payload shape. The runtime Parms buffer is guaranteed to match because UHT generates both the `_Script_Parms` struct layout and the `SignatureFunction` property metadata from the same source declaration.

## Source of truth

The delegate's `SignatureFunction` (a `UFunction` containing `FProperty` children matching each broadcast parameter). These properties provide both the **param name** (for TS generation and runtime JS key) and the **param type** (for serialization via `Swui_SerializePropertyValue`).

## Why ProcessEvent override instead of per-type Fire functions

The naive approach declares one UFUNCTION per delegate type:
```
FireBool(bool), FireString(FString), FireInt(int32), ...
```

This explodes combinatorially for multi-param delegates (bool+string, string+bool, int+string, ...). The generic approach overrides `UObject::ProcessEvent` on a single bridge class:

1. Bind a no-op `DelegateHook()` UFUNCTION to the observed delegate via `FScriptDelegate::AddDelegate`
2. When the delegate broadcasts, `ProcessDelegate` calls `ProcessEvent(this, HookFunction, &Params)`
3. Our `ProcessEvent` override checks `if (Function == HookFunction)`
4. Reads all parameters from the `Parms` buffer using the stored `SignatureFunction`'s `FProperty` list
5. Each property gives us the **original param name** (from the delegate declaration) and the **offset** within the Parms buffer

The offset match is guaranteed because UHT generates `_Script_Parms` structs and UProperty metadata from the same `DECLARE_DYNAMIC_MULTICAST_DELEGATE` macro. Verified against `OneVOnlineSubsystem.gen.cpp:309-317`:

```cpp
void FOneVBoolEvent_DelegateWrapper(const FMulticastScriptDelegate& OneVBoolEvent, bool bSuccess) {
    struct _Script_OneV_eventOneVBoolEvent_Parms { bool bSuccess; } Parms;
    Parms.bSuccess = bSuccess ? true : false;
    OneVBoolEvent.ProcessMulticastDelegate<UObject>(&Parms);
}
```

The `_Script_Parms` layout **is** the UProperty layout — they're generated by the same tool.

## Runtime flow

1. `USwuiSubsystem::ObserveDelegate` creates a `USwuiDelegateBridge`, stores the `SignatureFunction` pointer
2. Binds `DelegateHook` via `FScriptDelegate::BindUFunction` + `FMulticastDelegateProperty::AddDelegate`
3. When the delegate broadcasts, `ProcessMulticastDelegate` iterates the FScriptDelegate array
4. `ProcessDelegate` calls `ProcessEvent(Bridge, HookFunction, &Params)`
5. Override intercepts, reads each `SignatureFunction` property at its offset from `Parms`
6. Serializes to JSON: `Swui_QuoteJsonString(paramName) + ":" + Swui_SerializePropertyValue(prop, paramPtr)`
7. Dispatches: `document.dispatchEvent(new CustomEvent(namespacedKey, {detail: json}))`

## Important files

- `SwuiSubsystem.h` — `USwuiDelegateBridge` class declaration
- `SwuiSubsystem.cpp` — `ProcessEvent` override, `Init`, `ObserveDelegate`, `Swui_SerializePropertyValue`
- `SwuiTSGenerator.h` — `SwuiGetTSType` (same type mapping used for codegen)

## How to use it

1. Add a `UPROPERTY(BlueprintAssignable)` delegate to any UObject subclass
2. Register the class as a SWUI binding source (manual or via `SwuiExpose` metadata on the delegate property)
3. Regenerate bindings
4. JS receives typed CustomEvents matching the delegate params

No game-specific bridge code needed. Works for 0-param, 1-param, and multi-param delegates of any common type.

## Gotchas

- **CustomThunk + exec function approach considered and rejected**: A DECLARE_FUNCTION / DEFINE_FUNCTION based approach was explored but abandoned because the FFrame's argument stack doesn't contain the delegate's params when the called function has zero declared parameters. The `ProcessEvent` override receives the raw `Parms` pointer which is a C-style struct, not a UE stack frame.
- **Reference params** (e.g. `const FString&`) are handled correctly because the `_Script_Parms` struct stores the actual value, not a reference.
- **Param name alignment**: The generated TS event helper uses the same `SignatureFunction` property names, so runtime key names always match codegen.
- **Unsupported types**: If `Swui_SerializePropertyValue` can't serialize a param type, that field is omitted from the JS detail with a log warning.

## Debug checklist

- Bridge created in `ObserveDelegate`? Check `DelegateBridges.Num()`.
- `HookFunction` matches the actual `DelegateHook` UFunction pointer?
- `SignatureFunction` properties iterate correctly? Check `PayloadFields.Num()` in the observed delegate entry.
- `ProcessEvent` fires on broadcast? Set a breakpoint.
- JSON output has correct param names (from `SignatureFunction`, not hardcoded `"value"`)?
- `document.dispatchEvent` target matches what generated TS helpers listen on?
